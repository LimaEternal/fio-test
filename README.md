# FIO-Test — Автоматический бенчмаркинг накопителей

Автономный скрипт для автоматического тестирования производительности несистемных дисков на сервере с помощью утилиты `fio`. Скрипт сам определяет типы подключённых дисков (NVMe/SAS/SATA), поколение шины PCIe (Gen3/Gen4/Gen5), подбирает оптимальные параметры тестирования и выводит результаты в консоль и MD-отчёт.

## Структура проекта

```
fio-test.py              # Главный скрипт (точка входа)
configs/
  __init__.py
  nvme.py                # FIO-конфиги для NVMe + пороги
  sas.py                 # FIO-конфиги для SAS + пороги
  sata.py                # FIO-конфиги для SATA + пороги
utils/
  __init__.py
  scanner.py             # Определение дисков через lsblk + автоопределение PCIe Gen/Width
  reporter.py            # Генерация MD-отчёта
reports/                 # Папка для отчётов (создаётся автоматически)
```

## Зависимости

- Python 3.8+
- `rich` — вывод в консоль (таблицы)
- `fio` — утилита тестирования дисковой производительности (должна быть установлена в системе)

Установка Python-зависимостей:

```bash
pip install rich
```

Установка fio (Ubuntu/Debian/Astra Linux):

```bash
apt install fio
```

## Запуск

### Базовое тестирование (Параллельное)

По умолчанию тесты запускаются параллельно на всех несистемных накопителях одновременно, что идеально подходит для физических серверов с независимыми NVMe-дисками:

```bash
python fio-test.py
```

### Последовательное тестирование (-s / --sequential)

```bash
# Короткий флаг
python fio-test.py -s

# Полный флаг
python fio-test.py --sequential
```

Тесты выполняются строго по очереди (диск за диском). Рекомендуется использовать для:
- Виртуальных машин (QEMU/KVM), где виртуальные диски делят один физический накопитель хоста
- Дисков, подключённых к общему HBA-контроллеру
- Исключения взаимной конкуренции за I/O и получения максимально точных результатов

### С прекондишнингом

```bash
python fio-test.py --precond
```

Перед тестами выполнится запись 100% объёма каждого диска (bs=1M) для стабилизации производительности SSD. **Все данные на дисках будут уничтожены.**

### Свой путь для отчёта

```bash
python fio-test.py --output /path/to/report.md
```

По умолчанию отчёт сохраняется в папку `reports/fio_report_<дата_время>.md`.

### Изменение длительности теста

```bash
python fio-test.py --runtime 60
```

Каждый тест будет длиться 60 секунд вместо 30.

### Все флаги вместе

```bash
python fio-test.py -s --precond --runtime 60 --output result.md
```

## Пороговые значения (Thresholds)

Скрипт проверяет, удовлетворяют ли результаты минимальным требованиям. Каждый тест получает статус **done** (порог пройден) или **undone** (порог не пройден).

### Пороги по умолчанию

| Интерфейс | Тест | Порог |
|-----------|------|-------|
| NVMe | seq_read | >= 2000 МБ/с |
| NVMe | seq_write | >= 1500 МБ/с |
| NVMe | rand_read | >= 100,000 IOPS |
| NVMe | rand_write | >= 80,000 IOPS |
| SAS | seq_read | >= 800 МБ/с |
| SAS | seq_write | >= 600 МБ/с |
| SAS | rand_read | >= 30,000 IOPS |
| SAS | rand_write | >= 25,000 IOPS |
| SATA | seq_read | >= 400 МБ/с |
| SATA | seq_write | >= 300 МБ/с |
| SATA | rand_read | >= 10,000 IOPS |
| SATA | rand_write | >= 8,000 IOPS |

### Свои пороги

Для задания своих порогов используйте флаги `--threshold-*`. Формат: `seq_read_bw,seq_write_bw,rand_read_iops,rand_write_iops` (4 числа через запятую).

```bash
# Свои пороги для NVMe
python fio-test.py --threshold-nvme 3000,2000,150000,120000

# Свои пороги для SATA
python fio-test.py --threshold-sata 500,400,15000,10000

# Все интерфейсы сразу
python fio-test.py --threshold-nvme 3000,2000,150000,120000 --threshold-sas 1000,800,40000,30000
```

## Безопасность

**Критически важно:** скрипт работает напрямую с блочными устройствами (`/dev/*`). Тесты записи (`seq_write`, `rand_write`) перезаписывают данные на дисках. Восстановление невозможно.

Системные диски (содержащие корень `/`, `/boot`, `/boot/efi`, `/usr`, `/var`, `/home`, LVM-тома или подразделы на любой глубине вложенности) **автоматически рекурсивно исключаются из тестирования**.

## Какие тесты выполняются

| Тест | Режим | Блок | Потоки | Для чего |
|------|-------|------|--------|----------|
| seq_read | Последовательное чтение | 128k / 256k (Gen5) | 1..4 | Максимальная пропускная способность |
| seq_write | Последовательная запись | 128k / 64k | 1..2 | Максимальная пропускная способность на запись |
| rand_read | Случайное чтение 4k | 4k | 16 (Gen5) / 8 / 2 / 1 | Максимальные IOPS |
| rand_write | Случайная запись 4k | 4k | 8 / 2 / 1 | Максимальные IOPS на запись |

Параметры подбираются автоматически по типу интерфейса и версии PCIe Gen:
- **NVMe PCIe Gen5** — 4 потока bs=256k для исключения CPU Bottleneck (до 14 ГБ/с на чтение)
- **NVMe PCIe Gen4** — 2 потока bs=128k
- **SAS** — серверный профиль, 2 потока (QD64)
- **SATA** — строго 1 поток (QD32), AHCI не переваривает многопоточность

## Результаты

### Консоль

Результаты выводятся в виде чистой текстовой таблицы, полностью совместимой со сборочными серверами (Jenkins, GitLab CI) и любыми терминалами Linux.

### MD-отчёт

После завершения создаётся Markdown-файл в папке `reports/`:
- Список обнаруженных дисков (модель, серийник, интерфейс, PCIe Gen/Width, объём)
- Результаты тестов для каждого диска (блок, IOPS, МБ/с, Latency, статус)
