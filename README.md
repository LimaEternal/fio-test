# FIO-Test — Автоматический бенчмаркинг накопителей

Автономный скрипт для автоматического тестирования производительности несистемных дисков на сервере с помощью утилиты `fio`. Скрипт сам определяет типы подключённых дисков (NVMe/SAS/SATA), поколение шины PCIe (Gen3/Gen4/Gen5), подбирает оптимальные параметры тестирования и выводит результаты в консоль + MD-отчёт.

## СИНОПСИС

```
fio-test.py [ОПЦИИ]
```

## ОПЦИИ

| Флаг | Длинная форма | Описание |
|------|---------------|----------|
| `-c` | `--confirm` | Запросить подтверждение перед стартом тестов. Без флага тесты запускаются сразу (параллельно). |
| `-s` | `--sequential` | Запускать тесты последовательно (диск за диском) вместо параллельного режима. Рекомендуется для виртуальных машин. |
| `-p` | `--no-prefill` | Отключить предварительное заполнение (по умолчанию оно выполняется). Предварительное заполнение — запись 100% объёма каждого диска перед тестами: стабилизирует SSD и даёт корректные цифры записи (без него на пустых дисках скорости занижаются). Затирает все данные. Движок и параметры записи задаются в `configs/prefill.fio` (по умолчанию `ioengine=io_uring`, `bs=128k`, `iodepth=16`, `direct=1`); если движок не записывает ни байта в течение 8 секунд, скрипт один раз автоматически переключается на `psync`. Все диски заполняются параллельно. Прогресс — Rich-прогрессбар на каждый диск: проценты, объём, скорость, секундомер и ETA; данные берутся из живых JSON-статусов fio (`--status-interval=1`), т.к. счётчики `/sys/block/<name>/stat` на сервере не считаются. |
| `-l` | `--logging` | Подробное логирование: посекундный мониторинг линка/температуры/нагрузки в MD-отчёт, колонка Lat P99 и доп. поля NUMA/CPU-аффинити. Температура читается через `nvme smart-log` (нужен `nvme-cli`), нагрузка — из посекундных логов fio (`--write_bw_log`/`--write_iops_log`). Отчёт обновляется по мере завершения тестов (с живыми сэмплами идущих тестов). |
| `-o` | `--output ПУТЬ` | Путь для MD-отчёта. По умолчанию: `reports/fio_report_<timestamp>.md` |
| `-n` | `--no-tune` | Отключить автоматическую настройку системы для производительности (не применять `tuned-adm` и сопутствующие настройки). В режиме `-t` также отключает dry-run предпросмотр оптимизаций. |
| `-r` | `--runtime СЕК` | Длительность каждого теста в секундах. Если не указан — берётся `runtime=` из конфига `.fio` (например, NVMe: 60). |
| `-a` | `--add [N ...]` | Протестировать только указанные диски (номера или диапазоны из пронумерованного списка несистемных дисков, через пробел: `1 3-5`). Без номеров — список запрашивается интерактивно после показа нумерованного списка. |
| `-d` | `--delete [N ...]` | Протестировать все несистемные диски, кроме указанных (номера или диапазоны из списка, через пробел: `1 3-5`). Без номеров — список запрашивается интерактивно. |
| `-t` | `--test` | Тестовый режим: заполнить таблицу пробными значениями (`test` во всех ячейках) без запуска fio — для проверки вёрстки. Используются реальные диски из сканирования; если их нет — 5 фейковых разных интерфейсов. Флаги `-a`/`-d` работают как обычно, а `-s`/`-p`/`-r`/пороги в этом режиме игнорируются. |
| | `--threshold-nvme ПОРОГИ` | Свои пороги для NVMe. Формат: `seq_read=5000:seq_write=3000:rand_read=500000:rand_write=200000` (ключ=значение, разделитель `:`) |
| | `--threshold-sas ПОРОГИ` | То же для SAS. |
| | `--threshold-sata ПОРОГИ` | То же для SATA. |

## ПРИМЕРЫ

```bash
# Тестирование (запускается сразу, параллельно; префилл выполняется)
python fio-test.py

# Тестирование (с подтверждением перед стартом)
python fio-test.py -c

# Без предварительного заполнения (на свой страх и риск — цифры записи
# на пустых дисках будут занижены)
python fio-test.py -c -p

# Последовательный режим (для VM)
python fio-test.py -c -s

# 60 секунд на каждый тест
python fio-test.py -c -r 60

# Только диски 1, 2, 3 из нумерованного списка
python fio-test.py -a 1 2 3

# Диапазон: то же самое, что 1 2 3
python fio-test.py -a 1-3

# Все диски, кроме 4, 5, 6
python fio-test.py -d 4 5 6

# Номера и диапазоны можно смешивать: 1, 2, 3 и 5, 6, 7
python fio-test.py -a 1-3 5-7

# Флаг без номеров — скрипт покажет нумерованный список и запросит номера
python fio-test.py -a
python fio-test.py -d

# Тестовый режим (проверка вёрстки таблицы без реального прогона)
python fio-test.py -t

# Свой путь для отчёта
python fio-test.py -c -o /tmp/result.md

# Все флаги вместе
python fio-test.py -c -p -s -l -r 60 -o result.md
# Свои пороги для NVMe
python fio-test.py -c --threshold-nvme "seq_read=5000:seq_write=3000:rand_read=500000:rand_write=200000"
```

## Структура проекта

```
fio-test.py              # Главный скрипт (точка входа)
configs/
  __init__.py
  nvme.py                # FIO-конфиги для NVMe + пороги
  sas.py                 # FIO-конфиги для SAS + пороги
  sata.py                # FIO-конфиги для SATA + пороги
  prefill.fio            # Движок/параметры предзаполнения (по умолчанию), с авто-fallback
utils/
  __init__.py
  scanner.py             # Рекурсивное определение дисков + автоопределение PCIe Gen/Width
  reporter.py            # Генерация MD-отчёта
  prefill.py             # Предзаполнение: fio-конфиг, живой прогресс, fallback на psync
  format.py              # Форматирование байт/длительности/скорости
reports/                 # Папка для отчётов (создаётся автоматически)
```

## Зависимости

- Python 3.8+
- `rich` — вывод в консоль (таблицы)
- `fio` — утилита тестирования дисковой производительности (должна быть установлена в системе)
- `nvme-cli` — чтение температуры NVMe через `nvme smart-log` (только для `-l`)

```bash
pip install rich
apt install fio nvme-cli
```

## Что происходит при запуске

Скрипт сканирует систему, показывает системные (пропущенные) и целевые диски,
затем **сразу запускает тесты** (параллельно по умолчанию, с `-s` — последовательно):

```
$ python fio-test.py

Сканирование дисков...

Системные диски:
  /dev/nvme1n1 — KIOXIA KCMY1VUG3T20 (NVMe (PCIe Gen5 x4), SN: 7FP0A0CB0L03)
    (root: astra32087-lv_root)

Целевые диски:
  1. /dev/nvme0n1 — KIOXIA KCMY1VUG3T20 (NVMe (PCIe Gen5 x4), SN: 7FP0A0BJ0L03)

Режим: parallel
```

В режиме `-l` перед тестами также печатается заголовок «Выполнение тестов:»,
а после каждого завершённого теста — строка с его результатом
(`Готово /dev/nvme0n1 — Послед. чтение: 1.03M IOPS | 5800.0 МБ/с | lat 0.82 мс | PASS`);
итоговая таблица выводится в конце.

Чтобы сперва посмотреть список дисков и только потом подтвердить старт,
запустите с `-c` (`--confirm`) — перед тестами появится запрос
`Начать тестирование? [y/N]`.

## Выбор дисков вручную

По умолчанию тестируются все несистемные диски. Флаги `-a`/`--add` и
`-d`/`--delete` позволяют сузить набор, используя номера из нумерованного
списка, который скрипт печатает после сканирования:

```bash
python fio-test.py -a 1 3        # только диски 1 и 3
python fio-test.py -d 2 4        # все, кроме 2 и 4
```

Вместо отдельных номеров можно указывать диапазоны: `1-3` равносильно
`1 2 3`, а `5-3` — `5 4 3`. Номера и диапазоны смешиваются свободно:

```bash
python fio-test.py -a 1-3 5      # то же, что 1 2 3 5
python fio-test.py -d 2-4 6-7    # все, кроме 2 3 4 6 7
```

Если флаг указан без номеров, скрипт покажет нумерованный список и
запросит номера через пробел (диапазоны тоже работают):

```bash
python fio-test.py -a
# Целевые диски:
#   1. /dev/nvme0n1 ...
#   2. /dev/sda ...
# Номера дисков для теста (через пробел): 1-2
```

Флаги `-a` и `-d` взаимно исключают друг друга: использовать их
одновременно нельзя. Номера, выходящие за пределы списка, считаются
ошибкой, и запуск останавливается.

## Тестовый режим

`python fio-test.py -t` (`--test`) заполняет таблицу пробными значениями
(во всех ячейках — `test`) и генерирует MD-отчёт. fio не запускается —
удобно быстро проверить вёрстку консольной таблицы и отчёта на сервере,
не дожидаясь реального прогона.

Для проверки вёрстки используются реальные несистемные диски из сканирования
(так что их количество зависит от сервера); если целевых дисков нет — берутся
5 фейковых разных интерфейсов NVMe/SAS/SATA с предупреждением. Выбор дисков
через `-a`/`-d` работает как в обычном режиме. Флаги, не влияющие на вывод
пробной таблицы (`-s`, `-p`, `-r`, `--threshold-*`), в этом режиме
игнорируются и не попадают в отчёт — режим указывается как «тестовый».
`-l`, `-o` и `-n` продолжают действовать.

## Какие тесты выполняются

| Тест | Режим | Блок | Потоки | Для чего |
|------|-------|------|--------|----------|
| seq_read | Последовательное чтение | 128k / 256k (Gen5) | 1..4 | Максимальная пропускная способность |
| seq_write | Последовательная запись | 128k / 64k | 1..2 | Максимальная пропускная способность на запись |
| rand_read | Случайное чтение 4k | 4k | 16 (Gen5) / 8 / 2 / 1 | Максимальные IOPS |
| rand_write | Случайная запись 4k | 4k | 8 / 2 / 1 | Максимальные IOPS на запись |

Параметры подбираются автоматически по типу интерфейса и версии PCIe:
- **NVMe PCIe Gen5** — 4 потока bs=256k для исключения CPU bottleneck (до 14 ГБ/с на чтение)
- **NVMe PCIe Gen4** — 2 потока bs=128k
- **SAS** — серверный профиль, 2 потока (QD64)
- **SATA** — строго 1 поток (QD32), AHCI не переваривает многопоточность

Все тесты используют `--direct=1` для прямой работы с устройством в обход системного кэша (Page Cache) ОС.

## Пороговые значения (Thresholds)

Скрипт проверяет, удовлетворяют ли результаты минимальным требованиям. Каждый тест получает статус **PASS** (порог пройден) или **FAIL** (порог не пройден).

### Пороги по умолчанию

| Интерфейс | Тест | Порог |
|-----------|------|-------|
| NVMe | seq_read | >= 5000 МБ/с |
| NVMe | seq_write | >= 3000 МБ/с |
| NVMe | rand_read | >= 500,000 IOPS |
| NVMe | rand_write | >= 200,000 IOPS |
| SAS | seq_read | >= 800 МБ/с |
| SAS | seq_write | >= 600 МБ/с |
| SAS | rand_read | >= 30,000 IOPS |
| SAS | rand_write | >= 25,000 IOPS |
| SATA | seq_read | >= 400 МБ/с |
| SATA | seq_write | >= 300 МБ/с |
| SATA | rand_read | >= 10,000 IOPS |
| SATA | rand_write | >= 8,000 IOPS |

### Свои пороги

```bash
# Только для NVMe
python fio-test.py -c --threshold-nvme "seq_read=5000:seq_write=3000:rand_read=500000:rand_write=200000"

# Только для SATA
python fio-test.py -c --threshold-sata "seq_read=500:seq_write=400:rand_read=15000:rand_write=10000"

# Комбинирование порогов
python fio-test.py -c --threshold-nvme "seq_read=5000:seq_write=3000" --threshold-sas "seq_read=1000:seq_write=800"
```

## Безопасность

**Критически важно:** скрипт работает напрямую с блочными устройствами (`/dev/*`). Тесты записи (`seq_write`, `rand_write`) перезаписывают данные на дисках. Восстановление невозможно.

Системные диски (содержащие корень `/`, `/boot`, `/boot/efi`, `/usr`, `/var`, `/home`, LVM-тома или подразделы на любой глубине вложенности) **автоматически рекурсивно исключаются из тестирования**.

Рекомендуемый порядок работы:
1. Запустите сканирование: `python fio-test.py`
2. Проверьте список целевых и системных дисков
3. Убедитесь, что системные диски корректно распознаны
4. Запустите тесты: `python fio-test.py -c`

## Результаты

### Консоль

Результаты выводятся в виде чистой текстовой таблицы, совместимой со сборочными серверами (Jenkins, GitLab CI) и любыми терминалами Linux.

### MD-отчёт

После завершения создаётся Markdown-файл в папке `reports/`:
- Параметры запуска (команда и флаги)
- Список обнаруженных дисков (модель, серийник, интерфейс, PCIe Gen/Width, объём)
- Содержимое использованных `.fio`-конфигов
- Результаты тестов для каждого диска (блок, IOPS, МБ/с, Latency, статус)

Колонка `Lat P99 (мс)`, посекундные сэмплы линка/температуры/нагрузки
и секции «Мониторинг» добавляются в отчёт только с флагом `-l` (`--logging`).

P50/P90/P99/P99.9 берутся из перцентилей fio (`clat_ns.percentile`,
с откатом на `lat_ns.percentile`), загрузка CPU — из `usr_cpu`/`sys_cpu`
на уровне job (с откатом на `usage.usr`/`usage.sys`).

Если какой-то источник данных (метрик) недоступен (например, на сервере не установлен
`nvme-cli`), под таблицей «Сэмплы линка/температуры/нагрузки» печатаются
поясняющие заметки `> ...`, а колонки заполняются «—».

Нагрузка (скорость/IOPS) берётся из посекундных логов самого fio
(`--write_bw_log`/`--write_iops_log`, `--log_avg_msec=1000`) — отдельный
мониторинг не нужен: fio штатно пишет эти значения по секундам. Логи вливаются
в сэмплы после завершения теста, временные log-файлы удаляются.

Отчёт создаётся сразу после подтверждения запуска, а с флагом `-l` дополнительно
обновляется по мере завершения тестов: после каждого теста и (по тику) во время
выполнения — с живыми посекундными сэмплами текущего теста. Поэтому даже при
сбое или прерывании прогона в файле остаётся вся информация, собранная до этого
момента.
